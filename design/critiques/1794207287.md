## Whole
On the default screen the eye goes long file name → body title → Focus view; on the focus screen, body title → diagram → return action. The very entry for escaping the narrow panel and the way back are overshadowed by the document title, falling short of the goal of "a reading screen where the way back is always clearer". There is whitespace, but the density gap between header and body is large, and with the logo covered it is indistinguishable from a generic Markdown viewer.

## Findings
[blocker] focus-menu.light.760 · file name header — the long title runs on one line and disappears under the menu, with no visible way to see the full title — make the file name wrap at 760pt as well, and keep the full title reachable when enlarged.

[blocker] All 4 screens · return and keyboard state verification — only a conversation-origin screen is shown; board-origin return, Esc's close-menu → exit-focus, and scroll and keyboard focus restoration can't be confirmed from still images — final approval requires showing each origin's restoration result through actual transition checks.

[polish] default.light.760 · Focus view in the document header — buried among a small icon, the shortcut, and close beneath a two-line file name and path, the most needed escape action looks like an accessory tool — place it in a consistent position separate from the file name area, with a clear click target and visual boundary.

[polish] focus.light.1200 / focus-large.dark.760 · two-line top header — the return is small, the file name is bold, and the body title right below repeats it, so document identification outweighs the return — make the return action more identifiable and demote the file name to a secondary level that doesn't compete with the body title.

[polish] focus-menu.light.760 · top Esc hint and first menu row — the same “Esc closes menu” appears twice, and inside the menu it's laid out like an actionable item — show the close-menu hint in one place only, and switch to the exit-focus hint once the menu closes.

[polish] focus.light.1200 · flow diagram — center-aligned sentences smaller than body text break into three or four lines in narrow cards, interrupting the reading rhythm — base the horizontal layout threshold on actual text size and card minimum width, not just window width, and switch to vertical when space runs short.

[polish] focus-large.dark.760 · body side margins — at 150% the margins also grow about 1.5×, consuming width needed for long English sentences — keep body margins tied to window width and decouple them from text scaling.
